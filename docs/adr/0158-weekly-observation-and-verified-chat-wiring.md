# ADR-0158: Weekly Observation and Verified Chat Wiring

Status: Accepted for slice 0144; local qualification recorded separately.
Classification: security-critical.

## Decision

AI visibility re-observation is an independent 0135 research stage. Admission
reserves a conservative per-call standing spend ceiling and volume for the
existing question/provider plan. 0131 still owns cadence, question versions,
owner-enabled settings, monthly assistant holds and unknown outcomes. Closed
ports pin the deterministic run to its weekly handle and recheck authority;
completion cannot reserve or dispatch a different call. Provider billing remains
unreported, not invented or refunded.

Weekly chat reports require existing verified, opted-in owner report settings,
in addition to weekly standing admission. Version-one cycles queue through the
registered stage after closure; legacy cycles retain their existing trigger.
0133 owns bindings, link verification, epochs, recovery, suppression, provider
daily caps, fixed rendering and one-shot accepted/unknown outcomes. Email is
unchanged. Health registration uses 0142's durable alert events and authority,
not a new standing work type. Event/category/channel/binding/destination uniqueness
deduplicates chat fan-out; 0142's episode and hourly limits remain upstream.
No unverified recipient or new profile is admitted.

Bing page windows pin the current binding's latest eligible page import before
the cutoff, and select only the measured URL and reported UTC dates. Coverage and
unknown date granularity remain intact: `measured_as_reported`, never `complete`.
Missing page rows remain explicitly unavailable; site context is retained.

Astro IndexNow additions use literal configured `publicDir` (default `public`),
not the repository root. An offline baseline/candidate pair must preserve every
existing output artifact and add only the exact root-served key. The revision is
recorded as A4 in 0127's existing impact table, inheriting fresh owner review and
publishing checks; it is never standing-autonomy eligible. Other framework rules
and IndexNow's verified-live-key requirement remain unchanged.

## Consequences

No provider, credential or production deployment is enabled by migration.
Unconfigured stages show recorded unavailable reasons in the dashboard. See
[0144](../implementation/0144-loop-wiring.md) for qualification and live inputs.
